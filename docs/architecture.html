mlpipelinecheck 0.2.0

How a table becomes a report

The library checks the tables you already have. It looks for mistakes that make a test score look safer than it is. It stays on your computer.

1. You bring the table A CSV file from the command line, or a pandas DataFrame from Python. One call audits a dataset, a train/test split, or a file of predictions.
↓
2. The request is checked before any rule runs Duplicate column names, a missing target, and a group or time audit without the column you named are errors. The table is not rewritten, imputed, or uploaded.
↓
Dataset One table and the column you want to predict.
  • Empty table, missing values, duplicate rows
  • Constant and high-cardinality columns
  • Answer column used as an input, or copied under another name
  • One-class or badly unbalanced labels
Train and test Two tables you already split.
  • Same row on both sides
  • Same customer or other group on both sides
  • A test date that falls inside the training period
  • A large shift in labels or numbers
Predictions True answers and the model’s guesses. The model file is not opened.
  • Accuracy, F1, AUC, log loss, Brier score
  • MAE, MSE, and R² for regression
  • Optional resampled interval for independent rows
↓
3. Each hit becomes a finding The finding says what was measured, how serious it is, why it matters, what to do next, and what that check cannot prove. Raw rows and group ids are not copied into the report.
↓
JSON Sorted keys, for a script or a review. The timestamp changes each run.
HTML One file you can open in a browser. It does not call other sites.
Exit code 0 clear, 1 a serious finding, 2 a bad input or a broken check, 3 an unexpected error.

What sits behind it

PieceWhat it does here
Python 3.10+Runs the library.
pandasReads the tables you pass in.
numpyCompares numbers and resamples rows when you ask for an interval.
scikit-learnComputes the prediction scores. It does not train a model.
Python standard libraryWrites JSON and HTML, parses the command, and fingerprints rows.

A report with no findings means these checks found nothing. It does not mean the model or the split is free of leakage. Near-duplicate rows, a column that is only correlated with the answer, notebooks, and model files are outside this version.
